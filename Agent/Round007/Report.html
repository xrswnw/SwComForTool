  • UI新增校验级别选择(全/中/基本级)
  • 升级流程逻辑修正(校验级别传入、2字节响应解析)

3. 协议变更适配详情

3.1 FC=0x03 升级启动帧

旧格式: [FwSize 4B][FwCrc32 4B][FwVer 4B][BindVerify 4B] = 16字节
新格式: [FwSize 4B][FwCrc32 4B][FwVer 4B][BindVerify 4B][VerifyLevel 1B] = 17字节
                                                                          ↑ 新增
VerifyLevel:
  0 = 全级 (CRC32 + Size + MSP/Reset向量 + 绑定校验)
  1 = 中级 (CRC32 + Size + MSP/Reset向量)
  2 = 基本级 (CRC32 + Size)

3.2 FC=0x05 校验响应

旧格式: [Result 1B]
新格式: [Result 1B][Detail 1B]

Result码:
  0x00 = 通过
  0x01 = CRC32不匹配
  0x02 = 固件大小不匹配
  0x03 = MSP/Reset向量无效 (Detail: 0=MSP, 1=Reset向量越界)
  0x04 = 绑定校验失败

3.3 FC=0x07 设备信息响应

新格式 (偏移0 = Data[0]去掉Result后的位置，实际Data带Result前缀):
[0]     RESULT_OK
[1-12]  UID (12B)
[13-16] deviceUidHash (4B, LE)
[17]    PROTO_VERSION
[18]    Layer (0=BOOT, 1=APP)
[19]    deviceStatus
[20]    deviceAddr
[21-24] upgradeCount (4B, LE)
[25-40] hwVersion (16B, 字符串补零)
[41-56] swVersion (16B, 字符串补零)
[57-72] bootVersion (16B, 字符串补零)
[73-76] baudRate (4B, LE)

移除字段: commMethod, appFirmwareVer(数值), projectName
新增字段: hwVersion/swVersion/bootVersion字符串, Layer, deviceStatus, upgradeCount, baudRate

3.4 FC=0x01 握手响应

[0]     RESULT_OK
[1]     PROTO_VERSION
[2-5]   deviceUidHash (4B, LE)
[6]     Layer (0=BOOT, 1=APP)
[7]     deviceStatus
[8]     baudRateHint (波特率低8位，仅辅助判断)

变更: [8]原为baudRateIdx，现为baudRate低8位(协议传输优化)
上位机处理: 解析并日志输出，不影响逻辑(实际波特率由FC=0x07获取)

4. UI变更

4.1 新增校验级别选择

升级进度条旁新增ComboBox：校验级别

  • 全级(默认): CRC32 + Size + MSP/Reset向量 + 绑定校验
  • 中级: CRC32 + Size + MSP/Reset向量（跳过绑定校验）
  • 基本级: CRC32 + Size（仅完整性校验）

升级进行中ComboBox自动禁用，完成后恢复可操作。Tooltip含各级别说明。

4.2 版本信息显示增强

握手后版本信息框显示格式变更：

旧: "AD01 V1.0" (projectName + firmwareVersion)
新: "VET6-A01 V1.3 [BOOT:V1.0]" (hwVersion + swVersion + [BOOT:bootVersion])

日志同步增加Layer名称、升级次数、波特率信息。

5. 数据兼容性

向前兼容说明：
  • FC=0x03 verifyLevel参数默认值=0(全级)，不传参时行为与旧版一致
  • FC=0x07新格式解析采用渐进式判断(检查data.size()够不够长)，MCU返回旧格式时仍能解析protoVersion和部分字段
  • FC=0x05读取2字节响应时做了size()>=2的安全判断
  • DeviceInfo保留了projectName和firmwareVersion旧字段用于兼容，swVersion/hwVersion自动回填
