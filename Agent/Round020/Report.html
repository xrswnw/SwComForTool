日期: 2026-07-23  |  版本: V1.0  |  状态: 已修复, 备份 Round_094

一、查 macOS 崩溃报告

Round019 修复 hidapi 直接测试 OK, 但用户跑实际二进制仍 15s 超时. 查 /Users/swnw/Library/Logs/DiagnosticReports/SwComForTool-*.ips 发现 程序在升级过程中崩溃 (Data Abort), 不是 RX 接收问题!

1.1 崩溃栈 (最新 21:31:59)

ITransport::closed()            (信号 lambda 触发)
  → HidManagerMac::close()
    → HidManagerMac::~HidManagerMac()  (析构)
      → MainWindow::~MainWindow()
        → QWidget::~QWidget()
          → QObjectPrivate::deleteChildren()
            → QMainWindowLayout::statusBar() const
              [CRASH: Data Abort byte read Translation fault, FAR=0x1800]

异常: Data Abort (ESR=0x92000006). ESR dec: 0x92000006 = Data Abort Write (WnR=1 Wt=0). FAR: 0x1800 (极小地址, use-after-free 残留指针).

1.2 根因

MainWindow 析构链中:

  1. ~MainWindow() → Qt 子对象 deleteChildren
  2. delete HidManagerMac (MainWindow 子 QObject)
  3. ~HidManagerMac() 调 close()
  4. close() 末尾 emit closed() → 触发 MainWindow::onTransportClosed() lambda
  5. lambda 调 statusBar() 在 正在 delete 的 MainWindow 上访问 → Data Abort

本轮升级失败触发的 close() 让 CFRunLoop 线程析构, 析构链 emit 信号, lambda 访问 UAF.

二、修复方案

最小修复: 析构期间 blockSignals(true), 阻断 emit closed() 触发 lambda 访问 invalid MainWindow.

2.1 Fix: ~HidManagerMac blockSignals

文件: src/HidManagerMac.cpp

// Round 020: 阻止析构期间 emit closed() 触发 lambda 访问正在 delete 的 MainWindow
HidManagerMac::~HidManagerMac() {
    blockSignals(true);    // 阻断 emit closed/portError, lambda 不再触发
    close();                // 停 CFRunLoop, 清 m_rxBuf (内部也 emit closed, 已被 block)
}

blockSignals(true) 阻断此 QObject 派发的所有信号, 包括 emit closed(), emit portError(), emit dataReceived(), emit rawReceived().

不影响: 用户主动 close (按连接按钮) 路径不经过析构, closed 信号正常发出, UI 仍正常刷新.
