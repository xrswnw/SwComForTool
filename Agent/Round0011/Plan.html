当前代码现状分析

  • 传输层: 仅有 src/SerialPortManager.cpp（基于 QSerialPort），无任何 USB/HID 支持，MainWindow 全程硬编码依赖 m_serialManager。
  • 帧格式: src/ProtocolParser.cpp 当前使用帧头 0x44 0x41("DA") 与 MPEG-2 CRC32(poly=0x04C11DB7, 无反射, 无最终 XOR)。这是旧 AD01 协议。
  • Sw01 新协议: 帧头 0x53 0x77("Sw")，IEEE 802.3 CRC32(poly=0xEDB88320 反射, init/xor=0xFFFFFFFF)，FC 码与升级流程、设备信息解析与旧版一致。
  • USB HID: VID 0x5377 / PID 0x5378，报告 ID = 0x02，64B 包，EP1 IN / EP2 OUT。App 与 Boot 共用同一 VID:PID。本机已通过 Homebrew 安装 hidapi 0.14.0（含 CMake config 与 pkg-config）。
  • 15693: FC=0x15，子命令 0x00~0x08，响应统一带 [seq][total] 分片头；当前代码完全无此能力。
  • 升级流程: src/MainWindow.cpp 中 startUpgrade 仅按串口流程：握手→进入 Boot→轮询握手→数据→校验→执行。进入 Boot 后假设串口保持，对 USB 重枚举无处理。
  • 备份: 仅有 log_change.sh/watch_backup.sh 做 rsync 同步，无 Round 轮转全量快照脚本，不符合全局 CLAUDE.md 约束。

关键决策点（需确认）

决策 A — CRC32 算法是否一并改为 IEEE 802.3？

需求 3 只字面提及"帧头调整"，但 Sw01 协议文档明确帧校验为 IEEE 802.3(poly=0xEDB88320 反射)。若设备固件已按 Sw01 实现，工具必须用相同 CRC，否则所有帧校验失败、无法通信。

本计划方案: 同时更新帧头(→0x53 0x77)与 CRC32(→IEEE 802.3)，含 calcBindVerify(改为 Boot 文档的 Crc32CalcReflect：反射 CRC + UID 哈希后缀)。这是对旧 AD01 设备的 breaking change，旧设备不再兼容。若你的设备仍用 MPEG-2，请否决此项并告知。

决策 B — USB HID 依赖与平台

采用 hidapi 跨平台库。macOS 本机已具备(Homebrew)。CMake 新增选项 COMFORTOOL_ENABLE_USB(默认 ON)：
- ON 时 find_package(hidapi)，链接 hidapi::hidapi；找不到则配置报错并给出安装提示。
- OFF 时仅编译 COM 串口版，USB 选项在 UI 隐藏。
Windows 端需通过 vcpkg 安装 hidapi(vcpkg install hidapi)或手动放置；计划在 build_win.bat 补充说明。

决策 C — USB 升级固件分片大小

Sw01 文档存在矛盾：App §2 称"单包 data ≤ 56B"，但 64B 包剥报告 ID 后帧体 ≤ 63B(含 4B CRC)，反推 data ≤ 52B。本计划取保守值 48B/包（FC_FW_DATA 的 data = seq2+off2+fwdata，fwdata ≤ 48）。设备按更小包接收无副作用，可后续按实测上调。

决策 D — 15693 本轮范围

"先支持、功能后续触发" → 本轮只做 协议层：在 ProtocolParser 增加 FC=0x15 组帧/解析 + 分片重组。不新增 RFID 操作按钮；用户可通过现有"通信调试"面板(填 FC=0x15 + 子命令 hex 参数)手动触发验证。

决策 E — 备份路径

项目 CLAUDE.md 指定 /Volumes/Untitled 1/Files/BackupArea/ComforTool(回退 /Users/swnw/Documents/BackupArea)。备份脚本按此路径实现 Round 轮转全量快照，而非全局约束的 /Volumes/Record/Person Code/...。以项目专属规则为准。

Task 3: 帧头与 CRC32 对齐 Sw01 协议 协议

目标: ProtocolParser 帧头 → 0x53 0x77，CRC32 → IEEE 802.3，BindVerify → 反射 CRC+后缀。

3.1 改动点

位置当前改为
makeFrame 帧头0x44 0x410x53 0x77
parseFrame 帧头校验0x44 0x410x53 0x77
crc32()MPEG-2 poly 0x04C11DB7, 无反射, 无最终XORIEEE 802.3 反射 poly 0xEDB88320, init=0xFFFFFFFF, 最终 XOR 0xFFFFFFFF
calcBindVerify()MPEG-2 串联 UID 哈希反射 CRC(固件 + UID哈希小端4B 后缀) = Crc32CalcReflect
ProtocolParser.h 注释0x44 0x410x53 0x77 + IEEE 802.3 说明

3.2 新 CRC32 实现

quint32 ProtocolParser::crc32(const quint8 *data, int len) {
    quint32 crc = 0xFFFFFFFF;
    for (int i = 0; i < len; i++) {
        crc ^= data[i];
        for (int j = 0; j < 8; j++)
            crc = (crc >> 1) ^ (0xEDB88320 & (-(crc & 1)));
    }
    return crc ^ 0xFFFFFFFF;
}

3.3 不变项

FC 码(0x01/0x02/0x03/0x04/0x05/0x06/0x07)、响应 FC=Req^0xFF、length=1+N+4、设备信息 77B 解析、升级流程帧序——均保持不变。

4.3 响应解析 + 分片重组

struct RfidResponse {
    quint8 subCmd; quint8 seq; quint8 total; quint8 result;
    QByteArray payload; bool valid; QString error;
};
RfidResponse parseRfidResponse(const QByteArray &data) const;

// 分片重组器（按 subCmd 缓存，收齐 total 片后合并 payload）
class RfidFragReassembler {
    // key = devAddr+subCmd，存已收片；seq 到 total-1 全到则合并
    bool addFragment(const RfidResponse &frag, QByteArray &outFullPayload);
    void reset(quint8 devAddr, quint8 subCmd);
};

非 0x01 子命令 total 必须为 1，否则 RFID_FRAG_ERR。读块响应片0含 [result][data…]，后续片纯 data 续传，重组后去掉中间 [seq][total] 头。

5.3 USB 进 Boot 重连流程

// enterBoot 发出 FC=0x02 后，设备软复位 → USB 重新枚举
if (transport 是 HID) {
    m_hidManager->close();             // 旧 handle 失效
    for (i = 0; i < 20; ++i) {          // 最多 10s 重枚举
        QThread::msleep(500);
        枚举 VID 0x5377:0x5378 设备;
        if (找到) { m_hidManager->open(...); break; }
    }
    if (!m_hidManager->isOpen()) → 报错退出;
}
// 之后照常握手确认 layer==0 → 继续升级流程

COM 模式保持现状（端口常驻，复用同一 handle，仅轮询握手）。升级完成/失败后的最终握手检查同样在 USB 模式下处理重枚举。

5.4 waitForResponse 兼容 HID

现有 waitForResponse 依赖 m_rxBuffer 增长判断，HID 经线程 dataReceived 同样 append 到 m_rxBuffer，逻辑无需改动；仅确保 HID 单包即一帧（63B 内为完整帧），帧间间隔判定仍适用。

风险与注意事项

  • CRC/帧头变更使旧 AD01 设备失联，仅适配 Sw01 协议设备（见决策 A）。
  • hidapi 为外部依赖；CI/打包机若未装则需 -DCOMFORTOOL_ENABLE_USB=OFF 走 COM-only。
  • HID 读线程需正确停止与资源释放，避免退出时 hang；写路径 pad 至 64B。
  • USB 升级中设备重枚举有时间窗（数百 ms~数秒），重连重试上限 10s。
  • 遵守工程约束：全程不用 rm -rf，删除走 TrashCan/；备份轮转删旧 Round 也用 mv 至 TrashCan。
  • 15693 本轮无真实卡片可联测，仅保证组帧/解析逻辑正确性与编译通过，实卡验证留待后续触发。
