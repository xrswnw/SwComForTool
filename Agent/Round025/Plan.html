2. ZLR5401 协议中"电机控制"命令可用（FC=0x0A，步进电机 DRV8434S）

需求点名"电机旋转角度正转反转控制"，协议 §10 提供完整 6 个子命令，正好对应：

cmd名称Host→Device (data)说明
0x01MOVE 运动[cmd, dir, stepsL,stepsM,stepsH]dir=0 正转(CW) / 1 反转(CCW)；steps=24bit 微步数，0=持续运行
0x02STOP[cmd]停止并关断输出
0x03SPEED[cmd, hzL, hzH]设定微步/秒 (1~2000)
0x04TORQUE[cmd, pct]转矩百分比 (6~100)
0x05QUERY[cmd]查询 state/fault/stepsDone
0x06CLEAR[cmd]清故障回 IDLE

响应：func = 请求^0xFF(0x0A→0xF5)，data[0]=cmd，data[1]=err(0=OK)。协议另含 UHF(0x0B)/AM(0x0C)/开锁器(0x0D)，本轮聚焦电机（需求点名），其余作为后续可选（见第三节范围说明）。

二、方案设计

2.1 核心思路

完全对齐 SACCD 的交互范式，新增一个 ZLR5401 Area：

Supported Devices 边框
   └─ Sccd   (既有)
   └─ ZLR5401 (新增, 可勾选紫/绿)   --toggle-->  ZLR5401 Area (QGroupBox, 默认隐藏)
                                                        └─ TabWidget
                                                             └─ "电机控制" Tab
                                                                   └─ 正转/反转 + 角度 / 速度 / 转矩 / 持续 / 停止 / 查询 / 清错

所有内容用协议 FC=0x0A 封装发出，复用现有 m_parser->makeFrame() 与日志/收发链路，不改 ITransport / ProtocolParser 接口（D1 满足）。

2.2 电机控制 Tab 布局（本次新增）

方向按钮：正转(CW) / 反转(CCW) —— 点击即按当前参数发 MOVE（dir=0/1）。
角度输入：角度(°) QSpinBox（含负值？不，方向由按钮定，角度取 0~360；0°=持续运行，对齐协议 steps=0）。
微步换算：每转微步数 QSpinBox（默认 3200 = 200步×16微步，可改，因细分率设备端决定）。换算：steps = round(角度/360 × 每转微步)。
速度：微步/秒 QSpinBox（1~2000，默认 1000）→ MOVE 前先发 SPEED。
转矩：% QSpinBox（6~100，默认 50）→ MOVE 前先发 TORQUE。（可选，发 TORQUE 仅当启用勾选）
操作：停止 / 查询状态 / 清除故障。
只读输出：结果 文本框（显示 QUERY 的 state/fault/stepsDone 与各命令 err）。

角度→微步换算为上层便利设计；每转微步数默认 3200 需在确认时核准（协议未给细分值，做成可编辑输入，避免写死错误）。若确认后设备每转微步不同，改默认即可。

2.3 通用子命令收发 helper（新增）

bool sendZlrSubCmd(quint8 fc, quint8 subCmd, const QByteArray &argData,
                   QByteArray *outPayload, QString *outErrNote);
// makeFrame(fc, argData 前插 subCmd) → 收 → 校验 func==fc^0xFF → data[0]==subCmd
//                      → 打印 data[1]=err(0=OK) → outPayload=data.mid(2)
