二、设计方案

2.1 平台门面 HidManager.h 新增

新增 src/HidManager.h，按平台 using 别名，Mac 上 HidManager ≡ HidManagerMac，行为完全不变：

// src/HidManager.h —— 平台 HID 门面, MainWindow 仅依赖此名
#pragma once
#include <QtCore/QtGlobal>
#ifdef Q_OS_MACOS
  #include "HidManagerMac.h"
  using HidManager = HidManagerMac;
#elif defined(Q_OS_WIN)
  #include "HidManagerWin.h"
  using HidManager = HidManagerWin;
#endif

2.2 HidManagerWin.h / .cpp 新增 原生Win32 HID

原生 Win32 HID API，不引入第三方库（与 Mac 端“纯平台 API”风格一致）。接口与 HidManagerMac 1:1（ITransport + 静态 enumerate）：

  • enumerate(vid,pid)：SetupDiGetClassDevs(&GUID_DEVINTERFACE_HID) → SetupDiEnumDeviceInterfaces → SetupDiGetDeviceInterfaceDetail 取设备路径；逐个 CreateFile + HidD_GetAttributes 取 VID/PID 过滤；HidD_GetManufacturerString/ProductString/SerialNumberString 取描述；构造 HidDeviceInfo（path 为 \\?\HID#... 设备接口路径）。
  • open(params)：从 params["path"]（或 vid/pid 再 enumerate 取 path）CreateFile(GENERIC_READ|WRITE, FILE_SHARE_RW, OPEN_EXISTING, FILE_FLAG_OVERLAPPED)；起独立 QThread 跑 overlapped ReadFile 循环（对标 Mac 的 CFRunLoop 工作线程）。
  • writeData(data)：WriteFile 同步写。报告 ID 处理见 关键风险。
  • readAll()：锁内拷贝 m_rxBuf 并清空（与 Mac 一致）。输入线程完成回调锁内 append + emit dataReceived。
  • close()/isOpen()/name()/errorString()：同义实现。

三、关键风险与验证点

⚠ 最关键：HID 报告 ID（Report ID）在 Win 与 Mac 的差异

设备分析（依据 HidManagerMac 注释与实测）：单 HID 接口，Report ID = 0（无报告 ID），64B 报文，首字节 0x02 是设备协议前缀（非真实 Report ID）。

  • Mac 写：IOHIDDeviceSetReport(Output, reportID=0, pkt[64])，pkt[0]=0x02，设备在线收到 64B [0x02, <63B 帧>]。
  • Win 写（推测）：Windows 约定 Report ID=0 设备的 WriteFile 缓冲须首字节填 0x00（隐式 Report ID），后接 64B 报文，共 65B：[0x00, 0x02, <63B 帧>]；Windows 剥离 0x00，设备收到 64B [0x02, ...] = 与 Mac 一致 ✅。
  • Win 读（推测）：ReadFile 返回 65B [0x00, 0x02, <63B 帧>]，剥离 0x00 + 0x02 得协议帧（与 Mac 剥 0x02 等价）。

风险：若设备报告描述符的实际报告长度/Report ID 与上述推测不符，写可能 STALL/读可能错位。执行时需在真实 Win + 真机硬件验证，并准备回退变体：① 64B [0x02,<63>]（不加 0x00）；② 65B 不同对齐；用 HidD_GetPreparsedData+HidP_GetCaps 读取真实 OutputReportSize/InputReportSize 辅助判定。

其他注意
  • Windows HID 类自带驱动，SwCcrd(VID 5377/PID 5378) 通常即插即用，无需额外驱动安装。
  • QSerialPort 在 Win 由 Qt 提供，跨平台；UI 已隐藏 COM（TransportType::Com 暂不启用），保持现状。
  • Win 端无 .app bundle 的 HID 拉黑问题（Round 022 之前已查证为 macOS LaunchServices 特有）。
