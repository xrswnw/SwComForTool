三、Windows 端实现要点

3.1 Report ID 处理（与 Mac 对齐）

设备 Report ID=0、报文 64B、首字节 0x02 为协议前缀。Win32 HID class driver 约定 Report ID=0 设备的缓冲首字节为 Report ID（填 0x00），后接 64B 数据，driver 剥离首字节，设备侧收/发 64B [0x02, <63B 帧>]，与 macOS IOHIDDeviceSetReport(reportID=0, 64B) 等价。

  • 写 (writeData)：缓冲 [0x00, 0x02, <63B 协议帧>]，长度 = OutputReportByteLength(=65)。
  • 读 (读线程)：读回 [0x00, 0x02, <63B 帧>]，剥首字节(Report ID) 后入 appendRxFrame（再剥 0x02，与 Mac 同语义）。

3.2 报告长度动态适配

open 时用 HidD_GetPreparsedData+HidP_GetCaps 读取真实 InputReportByteLength/OutputReportByteLength，按其分配读写缓冲，未写死 65（对 Report ID=0 设备该值为 65）。

3.3 读线程与关闭

独立 QThread 跑 overlapped ReadFile 循环（对标 Mac CFRunLoop 工作线程）。close() 设 stop + CancelIoEx 让阻塞读返回 ERROR_OPERATION_ABORTED 后线程退出，再 CloseHandle。

四、关键风险（Win 端验证重点）

⚠ Report ID/报告长度假设需真机确认

上述 Report ID=0 / 65B / 首字节 0x00 的处理基于设备协议分析与 macOS 行为推断。Win 端首次连接真机时务必核对：

  • 看 %TEMP%/comfor_win_open.log 的 inLen/outLen（应均为 65）。
  • 若枚举/连接成功但通信无响应：可能报告对齐不符。回退变体：①写缓冲用 64B [0x02,<63>]（不加 0x00）；②读不剥首字节。届时反馈 inLen/outLen 与现象，我据情调整。
其他：Windows 自带 HID 类驱动，SwCcrd(VID 5377/PID 5378) 通常即插即用，无需额外驱动。QSerialPort 跨平台；COM 在 Win 仍不启用（UI 已隐藏）。
