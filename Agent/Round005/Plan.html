协议解析引擎 (ProtocolParser)

新建ProtocolParser类，实现帧组包/解析/CRC32/MPEG-2校验，支持APP+BOOT所有功能码

  • 新建 src/ProtocolParser.h/cpp，封装协议所有逻辑 [新增文件]
  • 帧格式: [0x44][0x41][DevAddr][Rsv=0x00][Length_LE16][FC][Data][CRC32_LE32]
  • CRC32: 多项式0x04C11DB7, 初值0xFFFFFFFF, 计算范围Header~Data
  • APP功能码: 0x01握手/0x02进入Boot/0x07设备信息/0xA0射频信息/0xA3射频控制/0x1A 1444A
  • BOOT功能码: 0x01握手(Layer=0)/0x03升级开始/0x04固件数据/0x05升级校验/0x06升级执行/0x07设备信息
  • 帧组装: makeFrame(DevAddr, FC, data) → QByteArray
  • 帧解析: parseFrame(QByteArray) → Frame struct (DevAddr/FC/Data/Result)
  • 校验Result=0x00为成功，0xFF FC为响应标志

功能区右侧增加"更新固件"按钮；握手成功后解锁功能区，初始和握手失败时禁用

3
握手协议 + 版本解析

握手按钮发送FC=0x01，解析响应：DevAddr填入verTopEdit，设备信息填入verBottomEdit

  • 发送: APP握手帧 FC=0x01 (DevAddr=verTopEdit内容或0xFF) [功能实现]
  • 响应解析: DevAddr=响应帧[2], Data[0]=ProtoVersion
  • verTopEdit显示DevAddr (十六进制如0x01)，可手动编辑
  • verBottomEdit显示: ProjectName + ProtoVersion + AppFirmwareVer
  • 超时5000ms无响应 → 日志报错"握手超时"
  • ProjectName不含"AD1" → 日志报错"设备校验失败"
注: BOOT层也有FC=0x01握手，响应Data[5]=Layer(0=Boot), APP层响应Data[0]=ProtoVersion(V2=2)，根据响应格式区分
4
固件更新流程 (IAP)

"更新固件"按钮: 选bin文件→BOOT升级序列(握手→开始→数据×N→校验→执行)→进度条

  • 选文件: QFileDialog打开，限制.bin后缀
  • 更新序列: FC=0x01(Boot) → FC=0x07(获取UID算bindVerify) → FC=0x03(开始,传FwSize/FwCrc32/FwVer/BindVerify) → FC=0x04×N(每帧512B) → FC=0x05(校验) → FC=0x06(执行)
  • 单帧数据长度固定512字节，最后一帧可能不足512
  • 进度条: QProgressBar显示 (当前帧/总帧数×100%)
  • 更新期间: 禁用握手栏所有控件+功能栏所有按钮+发送区
  • 失败: QMessageBox提示错误原因(Result码映射为文字)
  • 成功: 设备自动复位→等待设备重启→重新握手
bindVerify计算: 设备响应FC=0x07 Data[13~16]=DeviceUidHash(LE32)，直接作为bindVerify使用

日志区增加"保存"按钮，生成.md文件到项目根目录log文件夹

  • 文件内容: markdown格式，包含时间戳标题+日志时间线+设备信息
