协议解析引擎 (ProtocolParser)
功能说明
帧格式[0x44][0x41][DevAddr][0x00][Length_LE16][FC][Data][CRC32_LE32]
响应标志响应FC = 请求FC XOR 0xFF（如请求FC=0x01，响应FC=0xFE）
CRC32MPEG-2: 多项式0x04C11DB7, 初值0xFFFFFFFF, 范围Header~Data
APP功能码0x01握手/0x02进入Boot/0x07设备信息/0xA0射频信息/0xA3射频控制/0x1A 1444A
BOOT功能码0x01握手(Layer=0)/0x03升级开始/0x04固件数据/0x05升级校验/0x06升级执行/0x07设备信息
握手流程
1. 发送 APP握手帧 (DevAddr=verTopEdit内容或广播0xFF) 2. 等待响应(5000ms) → 解析DevAddr+ProtoVersion 3. verTopEdit 显示 DevAddr (0x01) 4. 发送 设备信息帧 (FC=0x07) 5. 等待响应(3000ms) → 解析 ProjectName+ProtoVersion+FirmwareVersion 6. verBottomEdit 显示 "ProjectName FirmwareVersion" (如 "AD01 V2.1.0") 7. ProjectName含"AD1" → 功能区解锁; 否则报错"设备校验失败"

设备信息偏移: 33~52(20B)ProjectName / 17(1B)ProtoVersion / 20~21(2B)FirmwareVersion

Boot层握手响应: Data[5]=Layer(0=Boot层响应)

固件更新流程 (IAP)
步骤指令说明
1FC=0x01 (Boot)Boot层握手，确认Layer=0
2FC=0x07获取设备UID，计算BindVerify
3FC=0x03发送固件元数据(FwSize/FwCrc32/FwVer/BindVerify)，擦除Flash
4FC=0x04×N分帧发送固件数据，每帧512字节，含Seq+Offset+Data
5FC=0x05四重校验(Size/CRC/MSP向量/BindVerify)
6FC=0x06保存参数，执行系统复位，3秒后自动重新握手

BindVerify: 设备信息响应Data[13~16] (LE32) 直接作为绑定校验值
