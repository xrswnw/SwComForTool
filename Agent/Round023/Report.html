三、实编译发现的源码 bug（计划外、必须修）

Plan 阶段静态审查认为源码无需改，但实编译推翻了该判断：HidManagerWin.cpp 从未在 Windows 上真正编译过（CMake 仅在 WIN32 编译此文件，Round022 引入后一直只做静态 review），两个 bug 潜伏至今：

错误位置原因修复
C1070 fatal: #if/#endif 不匹配文件首 L11 #ifdef Q_OS_WIN 到文件尾整文件由 L11 的 #ifdef Q_OS_WIN 包裹，但缺末尾 #endif（6 个 #if vs 5 个 #endif）。Mac 不编译此文件故未暴露。文件尾追加 #endif // Q_OS_WIN
C2664: 函数指针类型不匹配L186-188 hidWideString(hDev, HidD_Get*String)helper 声明 bool (WINAPI *)(HANDLE,PVOID,ULONG)，但 HidD_GetManufacturerString/ProductString/SerialNumberString 在 SDK 中返回 BOOLEAN（非 bool），MSVC 严格拒绝转换。参数类型改为 BOOLEAN (WINAPI *)(HANDLE,PVOID,ULONG)

这两个修复完全在 Windows 守护宏内，对 Mac 编译零影响。
