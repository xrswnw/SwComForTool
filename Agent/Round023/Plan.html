2. 构建与调试配置 — 存在问题（本轮修正对象）

问题 A：build_win.bat 严重过期，与现架构矛盾
  • 注释仍写 "USB HID 依赖(libusb-1.0)" "走 libusb 中断端点直连" "vcpkg install libusb" —— 实际已改原生 Win32 HID，零外部依赖（setupapi.lib/hid.lib 系统自带）。误导后续维护。
  • windeployqt 目标写成 ComforTool.exe（第49行），但 CMake 目标名是 SwComForTool，产物为 SwComForTool.exe → windeployqt 找不到文件而失败。
  • 提示文案自相矛盾：第43行说 build\Release\SwComForTool.exe，第49行又对 ComforTool.exe 部署。
  • QT_PATH 硬编码 arm64，无 x64 fallback（与 CMakeLists 的多路径探测不一致）。
  • 切换 Qt 路径时未清 CMakeCache.txt，旧 CMAKE_PREFIX_PATH 残留会导致重配失败。
问题 B：issue/pack.bat（Windows 打包）完全失效
  • findstr /c:"project(ComforTool VERSION" 匹配不到 —— CMakeLists 实际是 project(SwComForTool VERSION 1.0.0，版本号取空，包名错。
  • 引用 deploy\ComforTool.exe —— 实际产物 SwComForTool.exe，存在性检查必失败退出。
  • 包名 ComforTool%VERSION%_WinARM64 与实际工程名不符。
  • Qt6SerialPort.dll 复制路径与 windeployqt 流程重复/可能冲突。
问题 C：issue/pack.sh（macOS 打包）同名问题 涉及 Mac·仅构建配置
  • 同样 project(ComforTool VERSION 匹配不到 → 版本空；ComforTool.app 实际为 SwComForTool.app；包名 ComforTool_macOS。
  • 影响判断：仅修改打包脚本的命名/匹配字符串，不触碰任何 macOS 运行逻辑、源码、签名、bundle 配置，因此不影响 Mac 端功能；只是让 macOS 打包脚本真正可用（当前它本就是坏的）。
问题 D：.vscode/ 缺 Windows 调试配置
  • launch.json 5 个条目全是 macOS（SwComForTool.app/Contents/MacOS/... + lldb + DYLD_*），当前工作目录在 Windows 下无可调试条目。
  • tasks.json 仅有 macOS 构建/启动任务。
  • 需追加 Windows 调试与构建条目，不改动现有 Mac 条目（Mac 端零影响）。
问题 E（可选微调）：main.cpp 与 CMakeLists.txt
  • main.cpp 的 QCoreApplication::setSetuidAllowed(true) 是 macOS setuid Qt 安全检查绕过专用，Windows 上无意义。用 #ifdef Q_OS_MACOS 守护（Mac 行为不变）。
  • CMakeLists.txt Windows 端可补 RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/Release，让 SwComForTool.exe 直接落在 build/Release/（windeployqt 与 pack.bat 期望路径），避免多配置生成器下产物进 build/Release/ 或 build/ 不一致。
