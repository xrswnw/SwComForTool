九、版本 d 追加 — 首帧 HID 写入 BadArgument 超时修复

触发：用户实机测试反馈"打开软件发送的第一帧都超时，重发才成功"。日志 /tmp/comfor_rx_diag.log 定位根因。

根因
  • IOHIDDeviceSetReport 在打开后首次写入返回 kIOReturnBadArgument(0xE00002C2) —— macOS IOHIDInterface 刚 open 尚未完全就绪的 transient 错误。
  • 此时包未真正发出 → 设备无响应 → 3s 超时（rxBuf=0）。
  • 重发同一包即返回 0：升级路径自带 MAX_RETRIES 重试已自愈（历史日志 1004-1007：3×BadArgument→成功）；用户手动重发亦成功。
  • 手动握手会中招、升级不会：onFuncHandshake 只发 1 次就等响应 → 首帧 BadArgument 直接超时；升级路径有重试 → 自愈。
修复：在 HidManagerMac::writeData 内对 transient 类错误（BadArgument/NotReady/Offline）重试 SetReport，预算 30×30ms=900ms（远小于 3s 响应超时），成功即跳出。
  • 覆盖所有写入路径（握手/设备信息/发送/升级）—— 放 writeData 而非单点，统一。
  • 不动接口：writeData 签名不变；改动在 #ifdef Q_OS_MACOS 内，HidManagerWin.cpp 未触碰 → D1 满足，Win 零影响。
  • dev 机零开销：dev 机 attempt 0 即 rc=0 → 立即跳出（attempts=1），不触发重试。
  • 不掩盖真错误：仅对 transient 类重试，其它错误（设备真拔出等）立即返回。
验证
  • dev 机实跑（AX 驱动 Search→自动连接+握手）：diag 日志 attempts=1 rc=0x0 ×2（握手+设备信息），2 个 input_cb 响应，0 BadArgument → 正常路径无回归。✓
  • 重试路径：dev 机不触发 BadArgument（环境相关，15+ 次开/关均 attempt 0 成功），无法在本机实测；但"重试即成功"已被历史日志 + 用户手动重发证明，逻辑成立。
  • 用户侧确认（待用户在测试机重测）：用新包 issue/Mac_Arm64/ 或 issue/SwComForToolV1.0.0_macOS.zip 重测首帧握手，应不再超时；diag 日志若仍现 BadArgument，会显示 attempts=N 直至成功。
